## En une phrase

La base PostgreSQL du MVP contient maintenant le modèle multi-restaurants promis, avec un restaurant démo **Chicken Street Paris**, un menu minimal et une **table 14** adressable par jeton opaque.

---

## Ce qui a été livré

- Modèles SQLAlchemy 2 : restaurants, admin_users, tables, categories, products, option_groups, options, orders, order_items, order_item_options, payments (table vide, réservée).
- Migration Alembic `initial schema` appliquée sur la Postgres Docker.
- Seed démo :
  - restaurant **Chicken Street Paris** ;
  - catégories Burgers / Accompagnements / Boissons ;
  - produits Chicken Burger (12,50 € = 1250 centimes), Frites, Coca-Cola ;
  - supplément **fromage** (+1,00 €) ;
  - table **14** avec `public_token` opaque (pas le numéro dans l’URL).
- Tests automatisés (TDD) : jeton opaque, prix en centimes, `restaurant_id`, pas de colonnes PII convive sur les commandes, numéro de commande unique **par** restaurant, seed idempotent.

Toujours **pas** d’écran admin ni de menu public : ça arrive en S2–S3.

---

## Règles figées dans le schéma

- Argent en **centimes entiers**.
- Chaque ligne métier porte un `restaurant_id` (sauf admins internes).
- La table s’identifie par jeton, pas par `/table/14`.
- Aucune donnée personnelle de convive sur `orders`.
- `payments` existe mais reste vide (Stripe plus tard).
