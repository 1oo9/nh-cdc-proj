## En une phrase

On peut faire la démo **sur deux appareils** (téléphone convive + tablette cuisine) branchés au **même** serveur local, via le Wi‑Fi — sans cloud.

---

## Ce qui a été livré

- Runbook README : **Deux appareils (même stack LAN)** — boot, seed, trouver un jeton, URLs téléphone / cuisine.
- Script `scripts/lan_demo_env.sh` : génère les variables `.env` à partir de l’IP LAN.
- Compose lit `NEXT_PUBLIC_API_URL`, `PUBLIC_WEB_BASE_URL`, `CORS_ORIGINS` depuis `.env`.
- CORS configurable pour autoriser l’origine `http://<lan-ip>:3000`.
- Tests : parsing CORS + présence du runbook dans le README.

Hébergement cloud : **non** pour cette session (réserve si le LAN est déjà OK).

---

## Comment vérifier

1. `./scripts/lan_demo_env.sh` → coller dans `.env` → `docker compose up --build -d` + seed.
2. Téléphone (même Wi‑Fi) : `http://<lan-ip>:3000/t/<jeton>` → commander.
3. Tablette : `http://<lan-ip>:3000/cuisine/login` → voir le ticket sans F5 (ou ≤ 5 s).
